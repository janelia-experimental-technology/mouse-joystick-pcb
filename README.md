# mouse-joystick-pcb

Single-axis mouse joystick controller board for the Janelia Dudman lab
joystick rig, built as a native pyControl peripheral. One board drives one
joystick: an RP2040 runs a TMC5130A stepper driver with the joystick's
encoder and limit switch, a magnetic-particle brake, a torque-sensor bridge
and two analog outputs, and speaks a line protocol to pyControl over one
UART. The rig has two joysticks and two of these boards.

**Status, October 2026:** v1.0 is the fabricated revision, tagged `v1.0`.
Four assembled boards have been built by JLCPCB from the package in
[fab/mouse-joystick-pcb/](fab/mouse-joystick-pcb/README.md) (committed
2026-09-21). All four passed bench bring-up and ran the rig's trial task end
to end through pyControl running
[mouse-joystick-firm](https://github.com/peterpolidoro/mouse-joystick-firm):
units A and B were installed in Rig 1 on 2026-10-09, and units C and D run
the verification rig at Peter's desk since 2026-10-12. Every measurement
made on a board is in [the bring-up log](docs/bringup-log.md), under the
board's serial.

## What Is On It

| Connector | Carries |
| --- | --- |
| `J301` RJ-45 | pyControl behaviour port: the UART at 115200 8N1, and the port's 5 V, which powers the MCU when USB is absent |
| `J201` USB-C | firmware load, a USB serial console, and the other MCU power source |
| `J501` 2-pos 5.08 mm terminal | 36 V motor supply, behind a protected, firmware-switched high-side input |
| `J1102` 4-pos 3.5 mm terminal | stepper coils |
| `J1103` 5-pos 3.5 mm terminal | encoder: supply, return, A and B |
| `J1601` 2-pos 3.5 mm terminal | limit switch |
| `J1801` 2-pos 3.5 mm terminal | brake coil, driven by a 0 to 49 mA current sink |
| `J2001` 5-pos 3.5 mm terminal | torque-sensor bridge: excitation, signal pair, ground and shield |
| `J1101` BNC | joystick angle, 0 to 3.3 V analog out |
| `J901` BNC | torque, 0 to 3.3 V analog out |
| `J1301` 50-pin FFC | instrument port: 32 buffered digital taps for a logic analyzer |
| `SW601`, `SW602` | side-actuated buttons for the RP2040: BOOTSEL and reset |

The board has two power domains. The MCU domain runs from USB or from the
pyControl port's 5 V and is always on, so the board answers `ID` and `STATUS`
with the motor supply off. Everything else, the driver, the brake sink, the
torque front end and the analog outputs, runs from the 36 V input through a
switched high-side input that firmware controls, so pyControl can power-cycle
every peripheral to a known state without anything being unplugged.
[Power](docs/power.md) explains the chain.

The two joysticks use different motor and encoder cables so that the boards
and the firmware can be identical; a board carries no left or right state.
[Harness pinouts](docs/harness-pinouts.md) gives both cables and how a wrong
one shows up.

## Opening And Fabricating

KiCad 10 opens `kicad/mouse-joystick-pcb.kicad_pro`. The schematic and board
carry their own copies of every symbol and footprint; KiCad reports the
project's shared libraries as missing once and carries on, and the only loss
is the 3D models in the viewer, which the assembled STEP model under
`docs/generated/3d/` covers.

To order more boards, upload `mouse-joystick-pcb-jlcpcb.zip`,
`jlcpcb-bom.csv` and `jlcpcb-mouse-joystick-pcb-all-pos.csv` from
`fab/mouse-joystick-pcb/` to JLCPCB; the package's README records what was
validated and which placement rotations were corrected. To fabricate
elsewhere, plot the layers and drill files from the board in KiCad.
